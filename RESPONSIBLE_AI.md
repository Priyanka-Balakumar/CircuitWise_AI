# Responsible AI — CircuitWise AI

This document describes the responsible AI principles applied in the CircuitWise AI project.
It is intended for academic assessment, project transparency, and future maintainers.

---

## Project Context

CircuitWise AI is a college AI-for-sustainability project that uses machine learning to analyse
and optimise the energy consumption of IoT systems. IBM Bob is integrated as an engineering
explanation layer. The project is at a **calculated/simulated stage** — no hardware measurements
have been taken yet.

---

## 1. Transparency

### Value Labels
Every output produced by CircuitWise AI is explicitly labelled by source:

| Label | Meaning |
|---|---|
| **Calculated** | Derived from datasheet values using P = V × I_mA and E = P × (t / 60). Deterministic and reproducible. |
| **Predicted** | Output of the RandomForest ML model trained on synthetic data. |
| **Simulated** | Optimization savings estimated by mathematical scenario reduction (not experimentally measured). |
| **Measured** | Reserved for future ESP32 + INA219 hardware measurements. Currently: none exist. |

### Data Provenance
The `responsible_ai` block in `bob_context/circuitwise_results.json` embeds provenance metadata
in every exported session result. Bob's prompt explicitly requires it to communicate value source
in every response.

### ML Model
- Algorithm: `RandomForestRegressor(n_estimators=200, random_state=42, n_jobs=-1)`
- Training data: `CircuitWise_AI_ML_Dataset_V4_4.csv` — synthetic configurations generated from datasheet values
- Feature importances are printed by `ml/train.py` at training time
- Evaluation metrics (MAE, RMSE, R²) are printed at training time

### Anomaly Detection Model
- Algorithm: `IsolationForest(n_estimators=200, contamination=0.05, random_state=42)`
- Trained on the same synthetic dataset
- Label convention: 1 = NORMAL, −1 = ANOMALY (statistically unusual relative to training data)

## 2. Data Limitations

### Synthetic Training Dataset
The ML training dataset (`CircuitWise_AI_ML_Dataset_V4_4.csv`) was generated by applying
the same deterministic formulas (P = V × I, E = P × t) to component specifications from
public datasheets. It is **not derived from physical hardware measurements**.

Consequences:
- The RandomForest model learns patterns in calculated data, not real-world electrical behaviour.
- Prediction accuracy on real hardware is unknown until hardware validation is performed.
- The model may be highly accurate on synthetic configurations while diverging from measured reality.

### Component Data Quality
Values in `CircuitWise_AI_Component_Power_Dataset.xlsx` have variable quality:

| Quality level | Components |
|---|---|
| High (official datasheet) | ESP32, ESP32-S3, Raspberry Pi Pico, DS18B20, nRF24L01+, INA219, BMP280, MPU6050 |
| Medium (reputable product docs) | DHT22/AM2302, HC-SR04 |
| Low (module-level estimate) | HC-SR501, HC-05 |

Blank cells mean **no defensible universal value exists** in the source, not that the value is zero.

### Missing Modes
Some components (e.g. DHT22) have no documented sleep mode. Their `sleep_current_ma` is `null`.
This is represented as a missing mode, not as zero current. Zero and null are not equivalent.

## 3. Privacy

- No personal data of any kind is collected, stored, or transmitted.
- Component power specifications are sourced entirely from public datasheets and product pages.
- Session inputs (`session_input.json`) contain only electrical parameters — no user identity information.
- No data is sent to any external service. All computation is local.
- IBM Bob is used via the VS Code extension (local context) — no user data is transmitted via Bob integration.

---

## 4. Explainability

### Engineering Calculation
The power and energy formulas are classical, transparent, and fully auditable:
- Power: `P (mW) = V (V) × I (mA)`
- Energy: `E (mWh) = P (mW) × (duration_min / 60)`

No black-box logic is involved in the engineering calculation layer.

### ML Prediction
The RandomForest model is a tree-based ensemble. Feature importances are computed and logged
by `ml/train.py`. The 9 input features are explicitly listed in `FEATURES` across all relevant scripts.

The prediction is a single-point estimate. **No uncertainty quantification (confidence intervals)
is currently implemented.** This is a known limitation.

### Anomaly Detection
IsolationForest isolates anomalies by randomly partitioning feature space. The decision score
is a continuous value; the threshold (contamination=0.05) assumes ~5% of training data is anomalous.
The model identifies statistically unusual configurations — it does not perform root-cause analysis.

### IBM Bob
Bob is constrained by `bob_context/bob_prompt.md` to reference only values in `circuitwise_results.json`.
Bob explains; it does not compute. All Bob responses must include the data limitations disclaimer.
Bob cannot override, extend, or modify the Python engine outputs.

---

## 5. Safe Engineering Recommendations

### Optimization Safety
- The constraint-aware optimizer (`ml/optimizer.py`) respects a user-defined **minimum active time**
  per component. No optimization scenario is recommended that would reduce active time below this floor.
- Optimization savings are calculated projections from discrete 5%-step active-time reduction scenarios.
- They are **not experimentally verified** energy savings.

### No Hardware Safety Claims
CircuitWise AI does not assess hardware safety, thermal limits, current-carrying capacity, or
regulatory compliance. It analyses energy patterns only.

### Required Disclaimer
Bob's prompt requires the following disclaimer in every response:

> All values in this analysis are calculated or simulated using synthetic training data derived
> from component datasheets. No experimental hardware measurements have been taken.
> Hardware validation using ESP32 + INA219 is planned.
> These results are suitable for learning, estimation, and academic demonstration purposes.
> They must not be used as the sole basis for real system design without hardware validation.

---

## 6. Fairness and Bias

The training dataset is generated from datasheet values and contains no demographic, personal,
or sensitive attributes. Bias considerations are engineering-domain:

- **Selection bias:** The 16 components in the dataset are a limited, curated set. ML results
  generalise only to configurations similar to those in the dataset.
- **Mode availability bias:** Components without sleep mode data cannot benefit from sleep
  optimizations in the model, which may under-represent their optimization potential.
- **Synthetic data bias:** Because training data was generated from formulas rather than
  hardware measurements, the model may fail to capture real-world variability (noise, temperature
  effects, manufacturing tolerances, board-level parasitic losses).

---

## 7. Environmental and Sustainability Alignment

CircuitWise AI is designed specifically to reduce energy consumption in IoT systems.

- Reducing active duty cycle and promoting sleep modes directly reduces energy use.
- Lower energy use in battery-powered IoT systems extends battery life and reduces waste.
- The project aligns with UN SDG 7 (Affordable and Clean Energy) and SDG 12
  (Responsible Consumption and Production).

---

## 8. Future Work — Hardware Validation

The planned hardware validation phase will:

1. Connect an INA219 power monitor to measure actual current draw from the ESP32.
2. Run the same operating profiles used in the synthetic dataset.
3. Compare measured values against:
   - `engineering_calculation.system_total_energy_mwh` (calculated)
   - `ml_prediction.predicted_energy_mwh` (predicted)
4. Record measured values in a new `data/measured_power.csv` (column: `measured_energy_mwh`).
5. Retrain the ML model on a mixed synthetic + measured dataset.

Until this is done, all values remain in the **calculated/simulated** category.
